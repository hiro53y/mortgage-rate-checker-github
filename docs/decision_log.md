# 判断記録

## 2026-06-24

- 公式ページを取得できないだけで銀行行を取得失敗にしない。公式構造化APIを最優先し、取得不能時は価格.comの借換えランキング、価格.com銀行別ページ、ダイヤモンド不動産の当月表を銀行名・借換え・変動商品単位で構造解析する。
- 総合サイトの最小パーセント値を採用しない。口コミ金利、固定金利、手数料、団信上乗せ、過去年月を避け、当月の借換え変動商品の欄だけを採用する。
- 公式構造化値は `verified`、複数情報源が年0.150ポイント以内で一致した値は `corroborated`、単一情報源は `review` として画面上で区別する。照合元も表示し、出所不明の数値を作らない。
- 総合サイト照合値は比較用の参考値として表示するが、自動推薦は当月の公式構造化値または公式確認済み手入力に限定する。複数サイト一致は正確性を上げるが、団信・審査・優遇条件の適合を保証しないため。
- KV/Cronが未設定またはキャッシュ未作成でも、Pages FunctionsのGETはライブ取得へフォールバックする。運用設定漏れをユーザー画面の500エラーにしない。
- 403など非一時的な4xxは再試行せず、公式HTML診断は主URLを並列かつ短いタイムアウトで確認する。取得不能銀行を直列で待ち、全体を遅延させない。
- Cloudflareの `compatibility_date` はJST日付ではなく、デプロイ時点で未来にならないUTC日付を設定する。`2026-06-24` はUTC 2026-06-23時点のPages Functionsビルドを失敗させたため、`2026-06-23` に修正した。

## 2026-06-21

- 金利推薦値は汎用HTML正規表現から作らない。公式API/JSONまたは銀行別の確定アダプタだけを `verified` とし、汎用HTMLは診断表示に限定する。
- 広告下限金利と条件適合金利を別項目にする。融資率、年齢、残期間、団信上乗せを確定できない広告値を返済計算へ直接使わない。
- 借換え推薦は、当月・公式・条件適合、または公式URL・確認日・適用年月付き手入力に限定する。前月値、総合サイト、未確認手入力、条件不足値は除外する。
- 価格.comはShift_JISを復号して参考表示する。モゲチェックは静的HTMLに銀行別金利がないため、数値フォールバックから外す。
- 広島銀行は公式HTMLに住宅ローン金利表がないため、ダイヤモンド不動産の最新月表を参考表示するが、公式確認済み手入力になるまで推薦しない。
- 金利取得は画面操作から分離し、毎日06:00 JSTのWorker Cronで実行する。PagesのGETはKVキャッシュのみ、明示再取得は10分ロック付きPOSTとする。
- KVロックは重複抑制のベストエフォートであり強整合ではない。現規模では追加費用を抑えてKVを採用し、厳密な排他が必要になった場合のみDurable Objectへ移行する。
- Browser Renderingは初期実装に含めない。公式構造化データと静的アダプタで取得不能な銀行だけを第2段階の対象にする。

## 2026-06-13

- 住信SBIネット銀行の口コミ欄に出る過去年利 0.400% は、現在の借換え変動金利として扱わない。口コミ・評判・借入時期・金利種別の近傍にある数値は、金利候補から除外する。
- 広島銀行ページの 2.20% など、事務手数料・保証料・固定金利列・過去月表に由来する数値は現在の変動適用金利として扱わない。銀行別の想定レンジと日付行の先頭変動金利列を組み合わせて誤取得を抑える。
- 広島銀行のダイヤモンド不動産研究所ページは、月別金利表の最新月の変動金利列を優先する。過去月の低い金利を「最安」として選ぶと、現在条件の比較材料として誤るため。
- PayPay銀行・SBI新生銀行・auじぶん銀行は、モゲチェックや価格.comの借換え上位候補にも出やすいため、既存localStorageに行がなくても比較表へ補完する。借換え候補の母集団から主要ネット銀行が抜けることを避けるため。
- 「交渉優先度は低め」という表現は廃止し、現在金利と下限金利の上下関係をそのまま見出しにする。ユーザーが確認したいのは優先度ラベルではなく、`現在金利 - 下限金利` の事実と交渉材料になるかどうかであるため。
- 試算画面は「現在金利の判定」と「将来シナリオ別試算」を分離する。現在条件とシナリオ金利が混ざると、1.005%の表示と低め判定が同居して見える誤解につながるため。
- 比較表の差額列は「実質メリット」ではなく「12年累計差（月返済分）」と呼ぶ。諸費用・ボーナス返済・残期間全体を含む借換えメリットとは別物であるため。
- 借換え画面は、現在条件と候補条件の月返済・ボーナス返済・残り総返済額差・諸費用差引後を段階表示する。何と何を比較した数字かを画面上で説明できることを優先する。
- 比較表の基準行は `rowKind` で明示する。銀行名の文字列や `netBenefit === null` だけに依存すると、インポートデータ次第で基準判定が揺れるため。
- 実質的に候補を固定保存していない「この候補を保存」ボタンは削除する。ユーザーに保存済み候補が固定されたと誤解させないため。
- 実機で旧画面が残る場合の切り分けを容易にするため、画面下部にビルド表示を追加する。新旧が見た目で判定できないと、GitHub/Cloudflare/PWAキャッシュのどこで止まっているか判断しにくいため。
- Service Workerはv3に更新し、更新検知時に待機中Workerへ `SKIP_WAITING` を送る。スマホPWAで旧バンドルが残る問題は、コード修正だけでなくキャッシュの切り替えまで含めて対処する必要があるため。
- 初回設定・マイローン設定は固定フッターを持つ画面で操作するため、メイン領域の下余白を増やす。保存ボタンがフッター付近に寄ると金利変更保存の操作ミスにつながるため。
- 登録済み返済額と現在金利から逆算した概算額に差がある場合、金利比較と借換えでは概算額を比較元に使う。旧通知額を基準にすると、低い候補金利でも不利に見えるため。
- 次回返済日が過去日の場合、保存値は上書きせず、同じ返済日で未来月へ繰り上げた日付を試算用に使う。古い日付のまま残期間を計算すると、総返済額が過大になりやすいため。
- 借換え画面のメリット表示は、比較表の12年月返済差ではなく、残期間全体・ボーナス返済・諸費用込みで計算する。候補選定の基準は、後続対応で最新自動取得済み銀行の最低金利へ見直した。
- ホームの金額非表示は、警告カード内の登録額・比較用概算額にも適用する。残高や返済額を隠している状態で補足カードだけ金額が見えると、非表示操作の意味が崩れるため。
- 借換え候補の自動選択は、最新金利を自動取得できた銀行の中から判定使用金利が最も低い銀行を選ぶ。取得失敗・未取得・サンプル値だけ・手入力だけの銀行を候補にすると、公式最新値ではない低金利サンプルが借換え候補として表示されるため。
- 金利取得に失敗した銀行は、過去の `autoFetchedRate` を残さず未取得扱いに戻す。古い自動取得値が残ると、画面上は取得失敗なのに借換え候補として選ばれる可能性があるため。
- `/api/rates` は銀行ごとの複数URL、ページ内リンク探索、タイムアウト、文脈スコアリングで取得を試みる。ただし公式HTMLが `年--%` のような動的表示プレースホルダーしか返さない場合は、推測値を入れず取得失敗として扱う。
- 広島銀行はスーパー住宅ローン、住信SBIネット銀行はWEB申込コース借換ページを公式確認URLの優先候補にする。従来URLでは対象金利が静的HTMLから拾いにくく、ユーザー確認時点の該当ページとずれていたため。
- 公式ページから判断できない場合のみ、モゲチェック・価格.com・ダイヤモンド不動産研究所を総合サイトフォールバックとして使う。総合サイトの値は公式値ではないため `needs-review` の候補として扱い、画面上で公式確認を促す。
- 総合サイトでは「実質金利」ではなく「表面金利」「適用金利」「変動金利」を優先する。借換え返済額の概算計算に使うのは諸費用込みの実質金利ではなく、返済額計算用の金利であるため。

## 2026-06-12

- 金利変更シナリオの毎月返済額・ボーナス返済額・年間差額は、保存済みサンプル値ではなく現在条件から都度派生する。現在金利と同じシナリオは手入力返済額を正として年間差額0円にする。
- 試算カードの判定文言は、シナリオ金利と下限金利だけでなく現在金利との関係も見て表示する。現在金利が下限金利を上回る場合は、現在条件そのものを交渉検討水準として明示する。
- Service Worker は本番HTMLをnetwork-firstにし、キャッシュ名を更新する。旧バンドルがcache-firstで残ると、デプロイ後も古い試算ロジックが表示されるため。
- 開発環境ではService Workerを登録せず、既存登録と関連キャッシュを削除する。ローカル検証で古い画面を見て誤判定しないようにするため。

## 2026-06-07

- 比較表と借換えメリットは、金利変更シナリオではなく現在条件を基準にする。ユーザーがアプリ上で現在適用金利を更新した場合、その値が銀行比較と借換え判定の基準になるべきため。
- 毎月返済額・ボーナス返済額は自動上書きせず、銀行通知額の手入力を正とする。金利だけ更新され返済額が旧値に見える場合は、概算逆算額との差を警告として表示する。
- 借換え候補は保存済み固定値ではなく、比較表の非基準行から実質メリット最大の行を自動選択する。候補の公式確認や保障条件に未確認項目がある場合は警告を表示する。
- 既存の `deliverables/` 内ファイルは上書き禁止のため、修正版は別名の自己完結パッケージとして出力する。

## 2026-05-06

- 添付画像は指定パスで読めなかったため、プロンプト本文のUI要件を仕様の優先根拠とした。
- v1では外部URLを検索せず、プロンプト記載の固定URLのみを銀行マスタに登録する。
- Cloudflare Pagesで静的公開しやすいように、画面遷移はReact内の状態管理で実装する。
- 保存先はIndexedDBではなくlocalStorageを採用する。v1のデータ量が小さく、JSONエクスポート/インポートと相性がよいため。
- VitestはこのWindows実行環境でesbuild起動がEPERMになったため、テストはNode標準の `node:test` を各ファイル単体実行する方式にした。
- 借換えメリット画面の判定は、ユーザープロンプトの指定表示である「検討価値あり」をサンプル値として保持する。計算関数側の判定ロジックは仕様どおり別途テストする。
- 銀行公式ページの自動取得値は確定値ではなく「候補値」として扱い、判定優先順位を `手入力補正 > 自動取得 > サンプル` にした。
- 自動取得は毎月10日以降に銀行比較表を開いた場合のみ実行し、Cloudflare KV `RATE_CACHE` があれば当月結果を共有キャッシュする設計にした。
